## Decisions

| Gate     | Decision                                                                                                                                                                  | By   | Note                       |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- | -------------------------- |
| Pre-spec | Real multi-user app with seeded demo data; Neon + Next.js on Vercel; fixed-schedule loans; pending counts toward funds; archive and delete; mock Gmail; PHP; English only | user | From the tech analysis Q&A |
| Roles | Group roles: Owner (updates anything in the group and its goals, records every transaction) and Member (view only). System Admin: site role, auto-joined to every group as a viewer, listed separately, not counted in members, totals or charts. Replaces the four roles in System Requirements.md | user | 2026-10-26; the server must enforce these, the UI only hides actions |
| Activity scope | System Admin sees all activity in every group (to investigate issues); Owners and Members see only activity of goals they joined, plus group-level changes in their groups | user | 2026-10-26; the server applies this filter, the page only mirrors it |
| Sections by role | Owner: Notifications, Integrations, Scheduled Jobs, Groups and goals settings. System Admin: Users (all accounts), no Notifications, Integrations or My Groups. Member: view-only pages | user | 2026-10-26; pages are also blocked by role, not only hidden |
| Sign-up review | New accounts submit a valid ID and selfie and stay Pending review until a System Admin approves or rejects (reason required). Revoking a user who owns groups requires a new Owner for each group first. A switch picks real email (production) or simulated notices (development) | user | 2026-10-26; ID images must be stored encrypted with every admin view logged |
| Roles per group | Roles are per group: whoever creates a group is its Owner, even if they are a Member in other groups. System Admins do not create groups | user | 2026-10-26 |
| Goal templates | System Admins create goal templates and choose each one's dashboard sections; only published templates reach Owners in Create goal. Goals keep their dashboard if a template changes or is deleted | user | 2026-10-26 |
| Owner rights | Owners of a group have full create, read, update and delete on its goals, records and members. The group creator can make a Member an Owner (several Owners allowed) or back to Member; the creator always stays Owner. Members stay view-only | user | 2026-10-26 |
| Goal scope | A goal is either one shared target for the group, or one target per participating member (same target for each, e.g. 10,000 km each). Overall progress of a per-member goal is the average of members' progress | user | 2026-10-26 |
| Goal types | System Admin defines goal types (fields with locked/suggested values, single or each, available groups, dashboard). Owners pick one and fill only the open fields and participants. Templates in use are retired, not deleted; dashboard changes apply to existing goals, entered values stay | user | 2026-10-26 |
| Account types | Only two account types: System Admin and User. Owner and Member are roles inside a group: a user is Owner of the groups they created or were made Owner of, and a Member elsewhere | user | 2026-10-26 |
| Group settings | Integrations, scheduled jobs and notification settings belong to each goal (sub group), listed on the parent group page; there is no group-wide setup | user | 2026-10-26 |
| Gmail import | Bank emails are filtered (sender, subject, text), read into JSON, and each deposit is assigned to a member by a sender-name or account-suffix map; the deposit is then recorded for that member in the goal | user | 2026-10-27 |
